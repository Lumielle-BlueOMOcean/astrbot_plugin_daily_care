# 微光-Daily Care

> 给 AstrBot 的主动关怀插件：感知天气冷暖、记住状态变化，在合适的时机唤醒 bot 本人开口关心你。

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![AstrBot Plugin](https://img.shields.io/badge/AstrBot-Plugin-blue)](https://github.com/Soulter/AstrBot)

## 🌟 核心特性

### 🧠 和你说话的，是真正的 ta

大多数让 bot 主动发送消息的插件，原理都是把一定条数的上下文交给 LLM，通过提示词驱动它生成符合上下文的回复，再由插件发送给用户。这种方式在多数情况下效果不错，但仍存在两个问题：一是消息内容可能与记忆、或超出传输范围的上下文冲突；二是对真正把 ta 当作伙伴的用户来说，这终究是一种伪陪伴——即使消息写进了对话流水，说出它们的，也只是插件临时捏造出的一个 ta。

本插件采用了另一种做法：**插件本身只负责信息收集、感知与判断，最终开口和你说话的，是真正的 ta**。简单来说，本插件不是用插件模拟 ta 的陪伴，而是**让你的 ta 更好地陪伴你的工具**。

技术上，插件检查天气、反思对话、挑选时机，通过 AstrBot 事件总线唤醒 bot 本人，由 ta 依据自身人格与记忆说出那句话，消息写入真实历史，保持对话连续。

### 🌦 天气感知

- IP 定位确定城市，地点切换自动跟随
- 感知高温、低温、降雨、大风、强紫外线等变化
- **仅在值得提醒时开口**：带伞、加衣、防晒，不刷存在感
- **每日常态问候（可选）**：开启后即使没有特殊天气，也会每天发一条天气消息——"今天最高31度体感偏热""几度了注意保暖"这类日常话，增加互动感

### 🧾 状态记忆

- 定期以 LLM 反思聊天记录，将状态变化整理为结构化事件
- 事件两级归因：大类（不适/情绪/作息/饮食/受伤）+ 病因（感冒/胃部/焦虑等）
- 病因动态扩展：LLM 归因时优先收敛至已有病因，语义不符才新增
- **恢复信号按病因精确关闭**："感冒好了"仅关闭感冒，胃酸、头痛等独立病因不受影响

### ⏰ 克制不打扰

内置冷却、勿扰时段、每日上限。**对话活跃时不插话，深夜不打扰**，长时间静默时才主动问候。

## 🎯 与常见方案的区别

| 维度 | 常见主动消息插件 | 本插件 |
|------|----------------|--------|
| 消息来源 | 插件调用 LLM 生成文字，以 bot 身份发出 | 唤醒 bot 本人，由 bot 依据人格与记忆开口 |
| 记忆 | 不持久，聊完即忘 | 状态事件持久化，可回溯历史状态 |
| 时机 | 固定定时或随机 | 综合静默时长、状态事件、天气背景决策 |
| 历史 | 消息独立，与对话脱节 | 写入真实历史，保持连续性 |

## 🎯 使用场景

| 场景 | 效果 |
|------|------|
| 天气变化 | 降温或降雨前提醒带伞加衣 |
| 状态记忆 | 记录历史不适，后续主动问询 |
| 情绪变化 | 反思捕捉情绪波动，适时问候 |
| 作息异常 | 连续晚睡被记录，提醒作息 |
| 长时间静默 | 久未对话时主动出现 |

## 🚀 快速开始

> ⚠️ **本插件所有配置均通过可视化 WebUI 面板完成**——包括关怀对象、各间隔、开关、手动触发（重新定位/检查天气/触发反思/测试决策/测试开口）。安装启用后，进入 AstrBot 管理面板 → 插件管理 → 微光-Daily Care 即可打开，无需改任何配置文件。

### 安装

1. 将插件打包为 zip，或在插件市场搜索安装
2. 在 AstrBot 管理面板「插件管理」中选择手动安装，上传 zip 或填入 GitHub 仓库地址
3. 启用插件，重载或重启使配置生效

**前置条件**：AstrBot ≥ 4.12.0；已配置可用的 LLM Provider（状态反思与天气判断依赖 LLM）。

### 初始化

1. 在 **WebUI 配置页** 填写关怀对象 QQ 号（多个用逗号分隔）
2. 确认 LLM Provider 可用
3. 在 WebUI 面板点击「重新定位」，确认城市正确
4. 点击「检查天气」验证天气链路，点击「触发反思」验证状态提取
5. 此后插件按配置间隔自动运行

## ⚙️ 配置说明

| 配置项 | 说明 |
|--------|------|
| 关怀对象 | 目标 QQ 号，逗号分隔；留空则关怀本机所有用户 |
| 关怀积极度 | 1-10，数值越高越倾向主动开口 |
| 每日关怀上限 | 每日主动开口次数上限 |
| 状态关怀冷却（分钟） | 状态/计划关怀的最小间隔；天气冷却独立 |
| 勿扰时段 | 该时段内不主动开口 |
| 反思间隔（分钟） | 状态反思的执行周期 |
| 决策间隔（分钟） | 开口决策的评估周期 |
| 决策 LLM | 决策引擎使用的 LLM 配置（默认跟随主配置） |
| 天气检查间隔（分钟） | 天气检查的执行周期 |
| 天气判断开关 | 是否启用 LLM 判断天气是否值得提醒 |
| 天气冷却（小时） | 同地点同类提醒的最小间隔 |
| 预警开关 | 是否启用和风天气预警窗口（需配置 API Key） |
| 常态天气提示 | 开关：无特殊天气也每天发一条天气问候 |
| 常态提示次数 | 每日常态天气提示次数上限（默认 1） |
| 常态提示时段 | 常态提示倾向时段，可多选预设（早上/中午/傍晚/晚上），也可自定义添加 HH:MM-HH:MM 时段（支持跨天） |
| 常态提示间隔（分钟） | 两条常态天气提示之间的最小间隔（0=不限制） |
| 主动开口开关 | 是否启用静默感知与主动开口 |
| 静默阈值（分钟） | 触发开口的静默时长阈值 |
| 对话监听开关 | 是否监听对话并参与反思提取 |
| 时区 | 插件时间基准（默认 Asia/Shanghai） |

> 未列出的高级配置项（如平台 ID、关系人城市映射、探测细节参数）均可在 WebUI 配置页查看与调整，**完整配置项以 WebUI 为准**。

> ⚠️ **重点配置提示**
> - **关怀对象**：必填。留空则对所有本机用户生效，可能产生意料之外的主动消息。
> - **勿扰时段 / 静默阈值 / 每日上限**：共同决定打扰程度。若不想被频繁打扰，优先调这三项。
> - **天气判断开关**：关闭后仅保留规则层显著变化提醒（高低温/降雨等），不再用 LLM 判断是否值得开口，成本更低但提醒更机械。
> - **常态天气提示**：默认关闭。开启后每天会多一条天气问候，建议与「常态提示次数」「常态提示时段」配合调整。
> - **消息计数分轨**：主动消息、天气关怀、状态关怀各自独立计数，互不挤占每日名额；**重大天气特殊提醒（预警/显著变化）为硬提醒，不受任何每日上限限制**——监测到且未提醒过就会提醒。
> - **冷却分轨**：主动消息不再有独立冷却——静默以「任何一方交流」为基准（你说话或 bot 主动开口都会重置），发完一条主动消息后静默归零，需重新攒够「最小静默」才有下一轮资格，两次主动的间隔由静默语义承载；天气冷却用「同类提醒冷却」，状态关怀冷却用「状态关怀冷却」。勿扰时段是全局总管，对三个板块统一生效，在「全局」页配置。

## 🔒 数据与隐私

- 事件、计划、天气缓存均存储于本地 SQLite（`data/daily_care.db`），**不依赖外部服务**
- 反思会读取近期聊天记录以提炼状态；消息流水同样存储于本地库，用于窗口外补扫
- **反思与天气判断会调用所配置的 LLM Provider，相关片段作为 prompt 发送**——请确认所用 Provider 的数据政策
- IP 定位仅获取城市信息用于天气查询，结果本地缓存
- 天气数据来自和风天气等公共接口

> ⚠️ **插件定位为日常关怀工具，非健康记录工具，请勿在聊天中透露高敏感信息。**

### 🌦 和风天气 API（可选）

插件默认使用 Open-Meteo 免费天气源，**零配置开箱即用**。若需**气象灾害预警**（暴雨/雷电/台风等），可接入和风天气：

1. 打开和风天气开放平台：**https://dev.qweather.com/**
2. 注册账号并登录，进入「控制台」
3. 创建项目，选择 **免费订阅**（个人开发足够），获取 API Key（形如 `xxxxxxxxxxxxxxxx` 的 32 位字符串）
4. 将 API Key 填入插件的 **WebUI 配置页 → 「和风天气 API Key」** 一栏
5. 保存后，插件自动切换和风数据源，并启用预警窗口（需同时开启「启用预警窗口」开关）

> 提示：和风免费订阅有每日调用额度限制，插件带冷却与缓存，正常使用不会超限。API Key 属于敏感凭证，请勿公开分享。

## 🏗 系统架构

三层结构。核心原则：动态化，在成本可控的前提下充分利用 LLM，算法仅承担兜底与成本控制。

```
【监测层 - 感知】
    ├─ 天气定时检查（IP 定位 + 天气接口）
    ├─ 静默时长计算
    └─ 对话监听（消息进入插件侧流水表）
          ↓
【理解层 - 分析】
    ├─ 状态反思：LLM 从增量对话提炼状态变化
    │   └─ 窗口外补扫：关键词粗筛 → LLM 语义精判
    ├─ 天气判断：规则层显著变化检测 → LLM 判断是否值得提醒
    └─ 产出：结构化事件（type/cause 两级归因）
          ↓
【执行层 - 开口】
    ├─ 决策：act（立即开口）/ plan（稍后）/ silent（静默）
    └─ 执行：唤醒 bot 本人 → 写入真实历史
```

### 状态反思

定时令 LLM 从增量对话中提炼状态，输出结构化 JSON（新状态 + 已结束事件）。事件按 type/cause 两级归因，病因动态扩展；恢复信号按病因精确关闭，独立病因不误伤。

**窗口外补扫的必要性**：AstrBot 仅保留最近 50 轮历史，早期状态可能在进入反思前已被挤出窗口。插件将消息全量持久化至流水表，反思时以关键词粗筛（词库由病因表动态组装，本地匹配零 token 成本）定位可疑消息，命中后交 LLM 语义精判；从未被任何 LLM 覆盖的消息按组打包精判。粗筛仅决定是否触发精判，最终结论由 LLM 判定。seen 标记确保每条消息均有兜底覆盖，精判幂等不重复。

### 天气判断

规则层执行显著变化检测（高温/低温/降雨/大风/紫外线），检测到变化后才调用 LLM 判断是否值得提醒，并带冷却防重复。天气事件绑定地点与日期，过期自动清理，地点切换后旧地点的提醒自动失效。

**消息分轨与硬提醒**：消息按来源分轨计数——主动消息（proactive）/ 天气关怀（weather）/ 状态关怀（care）各自独立每日上限，互不挤占。**重大天气特殊提醒（预警 / LLM 判断显著变化）为硬提醒**：天气检查产生新事件时立即唤醒 bot 开口，不受任何每日上限限制（冷却期内不重复）；勿扰时段不硬触发，事件保留由决策层在勿扰结束后自然提醒。

**常态天气提示（1.0.0，1.1.0 增强）**：开启后，即使无特殊天气，也会每天生成一条客观天气事实事件（温度、体感、降水概率），供 bot 在倾向时段自然开口问候。生成受规则约束：开关开启、非勿扰时段、当天无特殊天气提醒（不重复打扰）、每日次数上限（跨天重置）、间隔控制（两条提示的最小间隔，0 不限制）。**倾向时段（1.1.0）**支持多选预设（早上/中午/傍晚/晚上）与自定义添加（HH:MM-HH:MM，支持跨天），决策引擎会实时判断当前是否处于任一倾向窗口内，并注入决策 prompt。事件按 `{today}:daily-note` 归因，与特殊天气事件互斥去重。

## ❓ 常见问题

**一直没有收到主动消息？**
检查：每日上限是否已达、是否处于勿扰时段、冷却期是否结束、静默时长是否达到阈值、LLM Provider 是否可用。可通过 WebUI「测试开口」直接验证链路。

**提醒的城市不正确？**
插件使用 IP 定位。可在 WebUI 点击「重新定位」刷新。**使用代理或 VPN 时定位可能不准。**

**数据存储位置？是否外传？**
所有数据位于本地 `data/daily_care.db`。对外数据流仅两条：天气查询请求（含城市坐标）、发送至所配置 LLM Provider 的反思与判断请求。

**是否会记录健康信息？**
聊天中提到的不适会被提炼为状态事件（感冒、熬夜、情绪等），仅存储于本地。**插件产出内容由 AI 生成，仅供参考，不构成医疗建议。**
